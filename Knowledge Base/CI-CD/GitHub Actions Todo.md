# GitHub Actions To-Do & Hands-On Lab Roadmap

This document organizes hands-on GitHub Actions implementation tasks, production lab challenges, and technical study milestones across the vault.

---

## 🧪 GitHub Actions Mastery Labs (Hands-On Path)
Work through these labs progressively to build production-grade CI/CD and platform engineering muscle memory:

- [ ] **Lab 1 — Foundational Workflow & Matrix Builds:** Build a multi-platform, multi-version test pipeline (`ci.yml`) leveraging matrix strategies (`include`/`exclude`), dynamic environment variables, step outputs, and concurrency cancellation controls.
  - *Verification:* `gh workflow run ci.yml && gh run watch`
  - *Theory:* [[GitHub-Actions/1. Workflows & Architecture|1. Workflows & Architecture]] & [[GitHub-Actions/2. Triggers & Event Filters|2. Triggers & Event Filters]]

- [ ] **Lab 2 — Passwordless AWS IAM OIDC Federation:** Configure an AWS IAM OIDC Identity Provider (`token.actions.githubusercontent.com`) and IAM role with scoped `StringEquals` subject claims (`repo:org/repo:ref:refs/heads/main`). Write a workflow requesting short-lived STS credentials without storing any static AWS keys.
  - *Verification:* `aws sts get-caller-identity` (executed inside workflow step)
  - *Theory:* [[GitHub-Actions/4. AWS OIDC & Enterprise Security|4. AWS OIDC & Enterprise Security]]

- [ ] **Lab 3 — Automated Terraform PR Pipeline with Infracost:** Deploy a full GitOps pull request workflow for Terraform code: run `fmt -check`, `validate`, `tflint`, `checkov` policy checks, run `infracost diff` for FinOps guardrails, and post formatted diffs and plan outputs as markdown comments on the pull request.
  - *Verification:* Inspect PR comments generated by `github.rest.issues.createComment` or automated action
  - *Theory:* [[GitHub-Actions/5. Terraform & IaC Automation|5. Terraform & IaC Automation]]

- [ ] **Lab 4 — Multi-Arch Container CI with GHA Caching & Trivy:** Configure Docker Buildx for `linux/amd64` and `linux/arm64`. Implement GitHub Actions cache backend (`cache-to: type=gha,mode=max`) to drop build times by 70%. Scan images with Trivy and upload SARIF results to GitHub Security.
  - *Verification:* `docker buildx imagetools inspect <image-name>:latest`
  - *Theory:* [[GitHub-Actions/6. Container CI & Caching|6. Container CI & Caching]]

- [ ] **Lab 5 — GitOps Delivery Bridge to ArgoCD:** Build an automated promotion pipeline: after container tests pass on `main`, an automated GitHub App or bot commits the updated image tag into the GitOps repository's Kustomize/Helm manifests, triggering ArgoCD synchronization.
  - *Verification:* `argocd app get <app-name> --refresh`
  - *Theory:* [[GitHub-Actions/7. GitOps Bridge & Release Orchestration|7. GitOps Bridge & Release Orchestration]]

- [ ] **Lab 6 — Ephemeral Runners with Actions Runner Controller (ARC) on EKS:** Deploy the GitHub ARC operator on an Amazon EKS cluster using Helm. Configure an `AutoscalingRunnerSet` running on AWS EC2 Spot Instances with Karpenter/Cluster Autoscaler to scale ephemeral runner pods from 0 to N based on workflow demand.
  - *Verification:* `kubectl get pods -n arc-runners -w`
  - *Theory:* [[GitHub-Actions/8. ARC & FinOps Optimization|8. ARC & FinOps Optimization]]

## ⚙️ Core Pipeline & Engineering Competencies

### 1. Workflow Architecture & Triggers
- [ ] Master context syntax: `${{ github.event }}`, `${{ secrets.* }}`, `${{ steps.<id>.outputs.* }}`
- [ ] Configure concurrency groups with `cancel-in-progress: true` to kill obsolete CI runs on push
- [ ] Set up fine-grained event path filters (`paths:` / `paths-ignore:`) for monorepo efficiency
- [ ] Implement manual triggers (`workflow_dispatch`) with typed inputs (boolean, choice, string)

### 2. Modularity & DRY Workflows
- [ ] Implement Reusable Workflows (`workflow_call`) with typed inputs, secrets, and outputs
- [ ] Author a Custom Composite Action (`action.yml`) bundling multi-step CLI commands
- [ ] Implement dynamic matrix generation using a pre-job generating JSON arrays for downstream jobs
- [ ] Establish centralized organization workflow templates

### 3. Enterprise Security & Supply Chain Defense
- [ ] Eliminate long-lived credentials across all repositories via AWS IAM OIDC
- [ ] Enforce top-level `permissions: {}` least-privilege defaults across all workflow files
- [ ] Configure GitHub Environments with Required Reviewers, wait timers, and deployment branch restrictions
- [ ] Pin 3rd-party actions to full commit SHAs (`uses: actions/checkout@11bd71901...`) with Dependabot automated updates
- [ ] Implement StepSecurity / Harden-Runner to detect outbound network exfiltration

### 4. FinOps & Performance Optimization
- [ ] Enforce `timeout-minutes` on all jobs to prevent runaway cost leaks
- [ ] Benchmark dependency caching (`actions/cache` vs setup actions native cache)
- [ ] Compare cost of GitHub-hosted compute ($0.008/min) vs ARC on AWS Spot Instances ($0.0015/min equivalent)
